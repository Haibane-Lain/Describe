# Reading-gap handoff: which component owns which question

Generated by `train.finetune.reading_gap`. Every figure is measured on the
VizWiz-VQA validation split against the deployed captioner
(`runs\blip_large_head\predictions_full_beam5.jsonl`).

## Why this document exists

The captioner answers questions about **objects** and **colours** reasonably
well and questions that require **reading text** poorly. Three attempts to
close that gap with more training data failed (text-aware subset, synthetic
degradation, answer-derived captions), and the architectural fix - training
the vision tower - is infeasible on this hardware at 6.5 h/epoch.

So this is a component-ownership question, not a modelling question.

## Handoff

| Question type | Owning component | Basis |
|---|---|---|
| object identity, scene description | **captioner** | 42.8% answer hit rate, 40.3% 4-gram match |
| colour | **captioner** | 51.9% hit rate; 43% of captions name a colour |
| whether an image is usable | **quality gate** | FA 4.79%, AUC 0.964; the captioner already hedges 20x more on unusable images but never refuses |
| printed text: labels, names, dates, prices, dosages | **OCR** | captioner reaches only 11.7% here |

**Open item:** the OCR component's hit rate on this same split has not been
measured here. Until it is, the project cannot state that the reading bucket is
covered - only that the captioner does not cover it. These 575 questions are a ready-made test set for that measurement.
